What is the Collatz Conjecture?

Pick any positive integer. Apply one simple rule repeatedly:

If n is even → n ÷ 2   •   If n is odd → 3n + 1

The conjecture states: every positive integer eventually reaches 1. No counterexample has ever been found, and no universal proof exists.

In PGC the runtime doesn't know what Collatz means. This page speaks only the operation identity collatz.compute across the governed transport boundary — it never names a workflow. The trace is verifiable evidence of what was computed.

FYI — recursion without a loop

Collatz is an inherently recursive computation: apply the rule repeatedly until you reach 1, with no known bound on how many steps that takes.

Yet PGC governs it as a finite, acyclic DAG (IN → compute → verify → store → exit) that the runtime traverses without any loop or recursion construct. The unbounded iteration is sealed inside a pure capability transform; the governed control flow itself never loops and never recurses. The platform therefore supports recursive / unbounded workloads without adding a loop primitive to the protocol — a non-obvious but foundational property of pure DAG traversal.
